## Properties that held

1. **Relations (§5)** — 600 random cases (all mass units and IU/U, every
   declaration, both directions and bases, µL/mL, five concentration units, C1
   objects on ~25 %) plus 60 C7-FX-14 discriminators; the oracle also ran over
   every other group. Ca = content ÷ (Vd′ + Dapp): worst relative error
   2.95e-16. Fa = Vd′ + Dapp bit-identical in 100 %. Vd′ = round3(Vd), half away
   from zero on the exact binary value in the displayed unit: 0 failures. Across
   142 cases where round3(round3(F) − Dapp) ≠ round3(Vd), the engine always
   showed round3(Vd). Displays, Dapp choice, treatment and labels: 0 failures.
   Three values within 8 ULP of a tie were set aside, not judged.
2. **Additivity (C7-IV-03)** — 0 violations. ADV-FX14-052 reaches exactly one
   unit (0.388 + 0.110 − 0.497 = 0.001) only because Dapp and Fa lie 0.005 and
   0.020 ULP from their ties — inside the zone C7-IV-03 and C7-FX-12 exclude.
3. **Invariances** (tolerances open; observed worst relative discrepancy):
   IV-01 forward 3.28e-16 / 1.70e-16 / 1.60e-16 (D / Dmin / none); IV-01 reverse

   Ca 0. Target-direction volume basis changes no output (80/80).
4. **Boundaries**, on / next double below / next above, operators as written:
   FL-08 f > threshold (and a case threshold = f) correct; FL-06 Fa > capacity
   correct; FL-07 Vd′ < minimum as decimals in µL correct, 0 false flags in 36

## Behaviours the URS does not specify (recorded, not failures)

Solids declared with "total vial contents" are ignored (D = content × v̄);
solids declared with "not recorded" leave displacement not computable; C7-HI-03
fires on a mismatched reportUnit in the volume direction; activity content with
a molar target gives HI-04 only; FL-06 compares doubles; "incomplete" is
returned for wholeVial false, a molar reportUnit, `0x50`/`Infinity`/`NaN`/empty,
Greek `μg`, `iu`, IU as a solids unit and similar; `80.`, `.5`, `+80`, `1,000`
and ASCII `ug` are accepted.

## Status after the fixes (main session, 28 September 2026)

- **F-2 fixed:** rejections are returned in §7 table order.
- **F-3 and F-4 fixed:** §7's value conditions (HI-01, 02, 06, 07) are
  evaluated on the exact entered decimals; a positive entry beyond the double
  range, or a positive quantity that underflows or overflows partway, makes the
  determination not representable, before C7-HI-08 can read 0 ≥ 0. HI-07 now
  compares masses exactly (the agent's "HI-07 below double precision" note).
- **F-1 fixed at its cause:** with the diluent known, C7-FL-08's 1 ÷ (1 − f) and
  f ÷ (1 − f) are computed as F ÷ Vd′ and D ÷ Vd′ — the same relations, since
  1 − f = Vd′ ÷ F — so 1 − f no longer cancels to zero. A 1e-300 mL diluent now
  gives a result (overstatement factor ≈ 7.3 × 10²⁹⁸, FL-07 and FL-08); only a
  factor genuinely beyond the double range (diluent 5e-324 or 1e-320 mL, factor
  ≈ 10³²²) is not representable. Regression tests in tests/engine.test.js.
- **Re-run of `suite.py` against the fixed engine: 3 residual items**, all at the
  edge of the double range, and each a question for the specification rather
  than an engine defect:
  - ADV-HOST-VOL-1e-300-DIL and ADV-HOST-SOL-1e300 — the oracle expects C7-HI-08
    because binary F = Vd′ + D equals D, while the URS states HI-08 "cannot fire
    when a diluent volume is entered". The engine follows the explicit sentence.
    (The independent spec audit raised the same point, its finding 16.)
  - ADV-HOST-VOL-5e-324-DIL — the oracle expects a result; the engine returns
    not-representable because the C7-FL-08 factor the URS requires exceeds the
    double range. Whether a flag payload is a "needed quantity" (convention 7)
    is for the specification owner.
