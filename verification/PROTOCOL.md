# Black-box comparison protocol — C7 Reconstitution

Protocol 2 (29 September 2026): adds the `extended` result block. Protocol 1
results (without it) are still read; `extended` is then reported as missing.

The interface between the shipped engine and any implementation written
without sight of it (acceptance 3). It fixes **what goes in and what comes
out**, and the conventions the URS leaves to the build. It does not say how to
compute anything: that comes from `spec/reconstitution-urs-v1.0.md` alone.

## Running

An implementation is a command that reads a JSON array of cases on stdin and
writes a JSON array of results on stdout, in the same order:

```
<command> < verification/cases.json > verification/cleanroom/results.json
node verification/compare.mjs --cmd "<command>"
```

`verification/cases.json` is generated by `node verification/export-cases.mjs`.
It carries inputs only — no expected values.

## A case (input)

```jsonc
{
  "id": "C7-FX-05",
  "direction": "target" | "volume",
  "content": { "value": "80", "unit": "µg" | "mg" | "g" | "IU" | "U" },   // value is the text as typed
  "contentBasis": "reagent-alone" | "total-vial-contents" | "not-recorded",  // ignored for IU/U content
  "provenance": "coa" | "nominal" | "weighed" | "not-recorded",
  "conjugate": "none" | "protein" | "conjugate" | "not-recorded",          // ignored for IU/U content
  "carrier": "present" | "absent" | "not-recorded",
  "wholeVial": true,
  "totalSolids": { "value": "100", "unit": "mg" } | null,                  // µg | mg | g
  "volumeBasis": "diluent" | "final",
  "target": { "value": "80", "unit": "mg/mL" },                            // direction "target"
  "volume": { "value": "1.00", "unit": "mL" | "µL" },                      // direction "volume"
  "reportUnit": "mg/mL",                                                   // direction "volume": the unit to report in
  "molarUnit": "µM" | null,                                                // unit of the molar form, if any
  "minTransfer": { "value": "2", "unit": "µL" },
  "capacity": { "value": "2", "unit": "mL" } | null,
  "c1": null | { "mw": { "value": 148.3, "unit": "kDa" | "g/mol" }, "massBasis": "assembled" | "monomer" | "conjugate" | "not-recorded", "flagCodes": ["C1-FL-08"] },
  "threshold": 0.006          // the C7-FL-08 material threshold in force (a configured constant)
}
```

Concentration units: `mg/mL µg/mL ng/mL g/L mg/L IU/mL U/mL M mM µM nM pM`.
Number text may use scientific notation (`1e6`). Every case in the file has a
complete set of declarations; incompleteness is not compared.

## A result (output)

```jsonc
{
  "id": "C7-FX-05",
  "status": "result" | "rejected" | "not-representable",   // not-representable: outside the double range (its own state)
  "rejections": ["C7-HI-08"],             // §7 codes, in §7 table order; [] unless rejected.
                                           // not-representable: the engine reports ["C7-HI-10"] (URS v1.1 §7)
                                           // and a "quantity" naming what is out of range — an implementation
                                           // SHOULD do the same, so that a decision is distinguishable from a
                                           // crash (standing rule 3). Compared: status only, until v1.1 is in spec/
  "flags": ["C7-FL-08"],                   // §8 codes raised, ascending by number
  "label": "achieved" | "obtained" | "at-most" | "uncorrected-for-displacement",
  "treatment": "computed" | "reagent-own-volume-only" | "not-computable-uncorrected",
  "molar": null | { "row": 7, "status": "reported" | "withheld" },   // §8 pairing row; null if no c1.
                                           // "reported" here means the pairing is PERMITTED; whether a value is
                                           // shown, or its unit was not selected, is extended.molar.status
  "unrounded": {                           // numbers, full double precision; null where undefined
    "F": 1.0, "D": 0.073, "Dmin": null, "Dapp": 0.073, "Vd": 0.927, "VdPrime": 0.927,
    "Fa": 1.0, "Ca": 80.0, "f": 0.073, "fmin": null, "target": 80.0
  },
  "displayed": { "diluent": "0.927", "final": "1.00", "concentration": "80.0000" }
}
```

For `rejected` and `not-representable`, only `id`, `status` and `rejections`
are compared.

### The `extended` block (protocol 2, 29 September 2026)

Every `result` also carries `extended`, the URS outputs the fields above do not
reach. Each field is defined by the requirement named; nothing here says how to
compute it.

```jsonc
"extended": {
  // C7-DT-04: "not-computable" exactly when the content basis is the total vial contents.
  "reagentConcentration": "computable" | "not-computable",
  // Rounding applied to displayed.concentration (decision of 28 September 2026).
  "concentrationRounding": "up" | "half-away",
  // C7-DT-07: the final volume is labelled "at least" (a lower bound) exactly when
  // Dmin is the displacement applied; its displayed value is then rounded down.
  "final": { "isLowerBound": true, "rounding": "down" | "half-away" },
  // C7-DT-07 / C7-FX-17, target direction only (else null): reported concentration ÷
  // target − 1, both in the displayed concentration unit; for a molar target the
  // target is its mass-concentration equivalent in mg/mL.
  "departure": null | { "unrounded": 0.004520, "display": "+0.452 %",
                        // taken on the unrounded values. Where the concentration is "at most", the
                        // departure is an upper bound too: isUpperBound true, rounded toward +∞ at 3 sf
                        // (spec/decision-2026-09-28-directed-rounding.md, addendum of 29 September 2026)
                        "isUpperBound": false, "rounding": "up" | "half-away" },
  // C7-FL-05's payload, present exactly when Dmin is applied (else null).
  "fl05": null | {
    "Dmin": { "unrounded": 0.0584, "display": "0.0584" },   // unrounded in mL; display in the displayed volume unit, 3 sf
    "fmin": { "unrounded": 0.0584, "display": "5.84 %" },    // Dmin ÷ F
    "exceedsThreshold": true                                  // fmin > threshold, strictly
  },
  // C7-FL-08's payload, present exactly when C7-FL-08 is raised (else null).
  "fl08": null | {
    "knownVolume": "final" | "diluent",       // C7-FL-08: keyed to the known volume, not the direction
    "factor": { "unrounded": 0.93197, "display": "0.932" },
      // final known: 1 ÷ (1 + f) — delivering the final volume as diluent gives this fraction of the intended concentration
      // diluent known: 1 ÷ (1 − f) — content ÷ diluent overstates the concentration obtained by this factor
    "percent": { "unrounded": 0.0680335, "display": "6.80 %" }
      // final known: the shortfall f ÷ (1 + f); diluent known: the overstatement f ÷ (1 − f)
  },
  // C7-DT-06 / §8 pairing, present exactly when a c1 object is given (else null).
  "molar": null | {
    "row": 7,
    "status": "reported" | "withheld" | "unit-not-selected",
    // unit-not-selected: pairing permitted, no molar target, and no molarUnit given (either direction).
    "of": "reagent" | "protein" | "conjugate" | null,   // what it is the molarity of: row 7, 8, 9; null unless reported
    "unit": "µM" | null,          // the molar target's unit, else the case's molarUnit; null unless reported
    "unrounded": 2.94 | null,     // the reported concentration ÷ the molecular weight, in `unit`; null unless reported
    "display": "2.94000" | null,  // 6 sf; rounded up where the concentration is "at most", else half-away
    "rounding": "up" | "half-away" | null
  }
}
```

Formats: a percentage displays the **fraction** rounded to 3 sf (half away from
zero, exact binary value) and then multiplied by 100 exactly, followed by a
space and `%`; zero displays as `0 %`. A departure carries an explicit `+` when
positive and an ASCII `-` when negative. A factor displays at 3 sf, half away
from zero. No exponent notation in any computed display; an entered value
(convention 3: an entered diluent) is displayed exactly as typed, which may include an exponent.

Comparison of `extended`: strings, booleans and nulls exactly; numbers bit-exact
or within the provisional relative bound, reported as for `unrounded`. Several
of these quantities have algebraically equal forms (1 ÷ (1 − f) = F ÷ Vd′), so a
last-bit difference here is expected and is not a disagreement.

## Conventions the URS leaves to the build

These are the build's choices. They are stated here so that a disagreement is
about arithmetic, not about units.

1. **Base units of `unrounded`.** Volumes (F, D, Dmin, Dapp, Vd, VdPrime, Fa) in
   **mL**. `Ca` and `target` in **mg/mL** for mass content, **IU/mL** or **U/mL**
   for activity content; a molar target is carried as its mass-concentration
   equivalent in mg/mL. `f` and `fmin` are plain fractions (0.073, not 7.3).
2. **v̄** is 0.73 mL/g, applied to a mass in grams.
3. **Displayed volumes** are in mL in the target direction, and in the entered
   volume's unit in the volume direction. `diluent` is Vd′ (an entered diluent
   exactly as typed); `final` is Fa at 3 significant figures.
4. **Displayed concentration** is Ca at 6 significant figures, in the target's
   unit (target direction), in mg/mL beside a molar target, or in `reportUnit`
   (volume direction). A value with fewer significant digits is padded with
   zeros (`80.0000`); a carry keeps n figures (`99.99…` → `100.000` at 6 sf,
   `100` at 3 sf). No exponent notation.
5. **Precision**: 3 sf volumes, 6 sf concentrations, half away from zero on the
   exact binary value of the double, in the displayed unit — **except a bound**
   (spec/decision-2026-09-28-directed-rounding.md): an "at most" concentration
   is rounded up, and an "at least" final volume rounded down, on the exact
   binary value.
6. **C7-FL-07** compares Vd′ as a decimal against the minimum, exactly, in µL.
7. **Out-of-range magnitudes.** If a needed quantity is not a finite positive
   double, report `"status": "not-representable"` (URS §7 has no code for it).
   This must be a decision the implementation makes on the quantity, **never a
   mapping of an unexpected exception**: an implementation that fails on a case
   reports `{ "id", "status": "error", "message" }` for that case (and still
   returns every other result). `error` is always counted as a disagreement.
8. **A rejection ends the determination**: rejections are collected in §7
   order before any computation, except C7-HI-08, which needs F and is
   evaluated when F is known. If any other rejection applies, HI-08 is not
   evaluated.

## How agreement is judged (verification/compare.mjs)

- `status`, `rejections`, `flags`, `label`, `treatment`, `molar`, `displayed`:
  **exact** equality.
- `unrounded`: each value reported as **bit-exact**, **within the provisional
  bound** (relative 1 × 10⁻¹², labelled provisional until outstanding item 3
  derives the tolerance), or **disagreeing**. A disagreement is a finding
  against *both* implementations until the URS decides it; neither side is
  presumed right.
